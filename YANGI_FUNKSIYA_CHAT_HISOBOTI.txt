1. FUNKSIYANING MAQSADI VA BIZNES MANTIG'I
--------------------------------------------------------------------------------
YechimUZ platformasida foydalanuvchilar quyidagi zanjir bo'yicha harakatlanadi:
1. Fuqaro, fermer yoki korxona o'z muammosini joylashtiradi (Problem Owner).
2. Tizim uni tahlil qilib, Challenge'ga aylantiradi.
3. Malakali dasturchilar va muhandislar (Solverlar) yechim taklifini yuboradi.
4. Muammo egasi yechimni ko'rib chiqib, ma'qullaydi (Shortlist qiladi).

YANGILIK:
Yechim ma'qullangan (Shortlist qilingan) paytdan boshlab, Problem Owner va
Solver o'rtasida to'g'ridan-to'g'ri ichki, shifrlangan va xavfsiz chat ochiladi.
Bu orqali tomonlar:
- Loyihani amaliy joriy etish detallarini;
- Pilot sinov joyi, muddati va texnik talablarini;
- Kelishuv shartlari va byudjetini
tashqi messenjerlarga (Telegram va b.) chiqmasdan, bevosita platforma nazorati 
ostida xavfsiz muhokama qilish imkoniyatiga ega bo'lishdi.

2. MA'LUMOTLAR BAZASI VA ARXITEKTURA O'ZGARISHLARI
--------------------------------------------------------------------------------
Mavjud arxitekturaga hech qanday zarar yetkazmagan holda, quyidagi 2 ta yangi
model ham lokal SQLite (prisma/schema.prisma), ham ishlab chiqarishdagi 
Neon PostgreSQL (prisma/schema.postgresql.prisma) sxemasiga qo'shildi:

A) ChatRoom (Chat xonasi):
   - id:         UUID birlamchi kalit
   - solutionId: Bog'langan yechim identifikatori (noyob - @unique)
   - problemId:  Tegishli muammo identifikatori
   - ownerId:    Muammo egasining foydalanuvchi IDsi
   - solverId:   Yechimchi (mutaxassis)ning foydalanuvchi IDsi
   - status:     "ACTIVE" yoki "CLOSED"
   - createdAt & updatedAt: Vaqt tamg'alari

B) ChatMessage (Chat xabarlari):
   - id:         UUID birlamchi kalit
   - chatRoomId: Tegishli chat xonasi
   - senderId:   Xabar jo'natuvchi foydalanuvchi IDsi
   - content:    Xabar matni (maksimal 2000 belgi)
   - isRead:     O'qilganlik holati (Boolean)
   - createdAt:  Yuborilgan sana va vaqt

--------------------------------------------------------------------------------
3. XAVFSIZLIK VA RBAC (ROLE-BASED ACCESS CONTROL)
--------------------------------------------------------------------------------
Chat tizimida qat'iy 3 bosqichli xavfsizlik nazorati o'rnatildi:

1. Yechim holatini tekshirish:
   - Chat FAQAT yechim "SHORTLISTED", "SELECTED", "PILOT" yoki "COMPLETED" 
     statusiga o'tgandagina faollashadi.
   - Hali ko'rib chiqilayotgan (SUBMITTED / DRAFT) yechimlarga chat ochilmaydi.

2. Shaxsiy daxlsizlik (Anti-IDOR / Anti-Eavesdropping):
   - Chatga FAQAT shu muammoning egasi (Owner) va shu yechimni taklif qilgan
     yechimchi (Solver) kira oladi.
   - Platformadagi boshqa begona foydalanuvchilar chatga kirishga yoki xabar 
     yozishga urinsa, tizim 403 Forbidden xatosi bilan ruxsatsiz kirishni bloklaydi.
   - Platforma nazorati va moderatsiyasi uchun faqat SUPER_ADMIN vakolatiga ega.

3. Xabarlarni o'qilganlik nazorati (Read Receipts):
   - Ikkinchi tomon xabarni ochib o'qishi bilan xabar holati avtomatik ravishda
     "o'qildi" deb yangilanadi.

4. API VA BACKEND XIZMATLARI (SERVICE LAYER)
--------------------------------------------------------------------------------
A) src/services/chat.service.ts:
   - getChatRoom(userId, solutionId): Xonani olish, ruxsatni tekshirish, o'qilmagan
     xabarlarni o'qildi deb belgilash.
   - sendMessage(userId, solutionId, content): Xabarni tekshirish, saqlash va 
     ikkinchi tomonga platforma ichki bildirishnomasini (Notification) yuborish.
   - getMyChatRooms(userId): Foydalanuvchining barcha faol chatlari ro'yxatini olish.

B) API Endpoints:
   - GET  /api/v1/chat/[solutionId] -> Chat xonasi ma'lumotlari va xabarlar tarixi
   - POST /api/v1/chat/[solutionId] -> Yangi xabar jo'natish
   - GET  /api/v1/chat/my          -> Foydalanuvchining barcha chatlari
